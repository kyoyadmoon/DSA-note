# Insertion Sort

Insertion sort 把陣列左側維持成一個已排序區，再逐一拿右側元素插入正確位置。它的動作就像整理手上的撲克牌：新牌進來時，從右往左比較，越過所有比它大的牌，停在第一個不大於它的值後面。

這頁使用相鄰交換呈現插入過程。待插入值每次只向左移一格，直到左側值不再比它大。這和「先保存 key、把較大元素右移、最後寫回 key」的常見實作具有相同排序結果與漸進複雜度，但會做較多次寫入。

## 每輪維持的 invariant

第 `i` 輪開始前，`a[0..i-1]` 已經由小到大排列，而且包含原陣列前 `i` 個元素。

本輪把原本位於 `a[i]` 的值視為 `key`：

1. 比較 `key` 和左邊的相鄰元素
2. 如果左值較大，就交換兩者，讓 `key` 向左一格
3. 如果左值小於或等於 `key`，或 `key` 已到達 `a[0]`，本輪結束

結束時 `a[0..i]` 已排序，所以下一輪能把已排序區再擴大一格。完成 `i = n - 1` 後，整個陣列都位於已排序區。

## 為什麼適合近乎排序的資料

Insertion sort 的工作量取決於逆序對數量。逆序對是索引 `p < q`、但 `a[p] > a[q]` 的元素配對；這頁的相鄰交換版本每次交換恰好消除一個逆序對。

- 已排序輸入沒有逆序對：每輪比較一次就停下，共 `n - 1` 次比較
- 反向排序輸入有 `n(n - 1) / 2` 個逆序對：每個新元素都要一路移到最左側
- 只有少數元素錯位時，需要的交換也少，因此實際執行時間接近線性

這種自適應特性是它和 [Selection Sort](/sorting/selection-sort) 的主要差異：Selection sort 即使面對已排序輸入，仍要掃完每個未排序區。

## 複雜度

| 情況 | 比較與移動 | 時間 |
|---|---:|---:|
| 已排序 | n - 1 次比較、0 次交換 | O(n) |
| 平均 | 與平均逆序對數同階 | O(n²) |
| 反向排序 | n(n - 1) / 2 次交換 | O(n²) |

演算法只使用 `i`、`j` 和交換暫存值，因此額外空間是 `O(1)`，屬於 in-place 排序。

## 為什麼穩定

迴圈只在 `a[j - 1] > a[j]` 時交換。當兩個值相等時條件為 false，右側元素會停在左側同值元素之後，因此相等元素不會互相跨越，原始相對順序得以保留。

如果把條件改成 `>=`，相等元素也會交換，穩定性就會消失。這個細節也適用於使用右移寫法的版本。

## 相鄰交換與右移版本

| 實作 | 每次向左移動 | 特性 |
|---|---|---|
| 本頁相鄰交換 | 交換 key 與左鄰元素 | 動畫能保留完整元素身份，步驟直觀 |
| 常見右移版本 | 複製左值到右側，最後寫回 key | 同樣是 O(n²)，但通常減少陣列寫入次數 |

兩種版本的比較順序、穩定性與最好／最壞時間界線相同。若元素搬移成本高，實務上通常採右移版本。

## 跟其他基礎排序比較

| 排序 | 最好時間 | 平均 / 最壞 | 穩定 | 主要動作 |
|---|---:|---:|---:|---|
| [Bubble](/sorting/bubble-sort) | O(n) | O(n²) | 是 | 反覆掃描相鄰逆序 |
| [Selection](/sorting/selection-sort) | O(n²) | O(n²) | 否 | 每輪選最小值做長距離交換 |
| **Insertion**（本頁） | O(n) | O(n²) | 是 | 把新元素插入已排序前綴 |

## 常見應用

- 小型陣列：迴圈短、額外空間固定
- 近乎排序的資料：執行時間會隨逆序對減少
- 混合排序的子程序：部分高效排序會在子陣列很小時切換到 Insertion sort
- 線上輸入：每收到一個新元素，就能插入既有已排序序列
